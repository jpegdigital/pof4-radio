# The Program Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A durable `/program` page, in its own route group, that plays a pre-generated CHR radio segment with two audio lanes — Spotify (music/bed) and one `<audio>` (mic) — ducked, bedded and back-timed against each other.

**Architecture:** Everything lives under `apps/web/src/app/(program)/`: a pure reducer that emits the *desired* state of both lanes, one effects hook that makes the device and the audio element match it, and a page that renders the cue sheet as a timeline. Only the Spotify device hook and the account module are imported from the station.

**Tech Stack:** Next.js App Router, React 19, Vitest, Spotify Web Playback SDK (via `use-spotify-device.ts`), pre-generated ElevenLabs clips in `apps/web/public/program/`.

**Spec:** `docs/superpowers/specs/2026-08-29-program-design.md`

## Global Constraints

- No new packages (CLAUDE.md: always minimize dependencies).
- No server or schema changes; nothing under `app/(app)` changes.
- Cross-group imports only: `@/components/station/use-spotify-device` and `@/components/station/spotify-account`.
- Levels: `FULL 0.8`, `DUCK 0.3`, `BED 0.25`; `TAIL` 1000 ms; ramp-up ~500 ms, duck-down immediate.
- LF line endings; `pnpm check` must pass (lint, format, typecheck, test).
- Tests are pure logic only (`*.test.ts` next to the code).

### Task 1: The reducer

**Files:**
- Create: `apps/web/src/app/(program)/program/reducer.ts`
- Test: `apps/web/src/app/(program)/program/reducer.test.ts`

**Interfaces:**
- Produces: `Track`, `Talk`, `Element`, `Level`, `ProgramState`, `ProgramEvent`, `initialState`, `reducer(s, e)`, `onAir(s): Element | null`.

- [ ] **Step 1: Write the failing tests** — the cases: RUN starts element 0 with the bed under and the clip on the mic (`playSeq` 1, `startedAt` set); RUN after STOP restarts the element at the cursor; RUN while running is a no-op. Lanes: a song without talk → `{uri, "full"}`, mic null; an intro talk → `duck` + clip; an outro talk → `full`, mic null, and `OUTRO_DUE` → `duck` + clip; an id → `{null, "off"}` + clip. CLIP_ENDED: on an intro talk → mic null, level full, cursor and playSeq unchanged; on a break → next element; on an outro talk → mic null only (level stays duck); a stale clip name is ignored; CLIP_FAILED behaves as CLIP_ENDED. TRACK_ENDED → next element; past the last element → loop stopped, cursor kept, lanes silent; ignored while stopped. STOP silences both lanes and keeps the cursor; NEXT/PREV move and bump playSeq, PREV at 0 is a no-op; JUMP out of bounds is a no-op, JUMP while stopped starts the loop; HALT stops with the error.

### Task 3: The effects hook

**Files:**
- Create: `apps/web/src/app/(program)/program/use-program.ts`

**Interfaces:**
- Consumes: `SpotifyDevice`, the reducer, `clipUrl`.
- Produces: `useProgram({device, elements}) → { state, dispatch, clips: ReadonlyMap<string, ClipEntry>, micClock: MicClock | null, unlock }`, `ClipEntry = {url, durationMs} | {error}`, `MicClock = {paused, position, duration, at}`, `LEVELS = {full: 0.8, duck: 0.3, bed: 0.25}`.

- [ ] **Step 1: Write the hook** — five effects, mirroring `use-station.ts`:
  1. Clips: at mount, fetch every clip named by the elements into blob urls and measure with a metadata-only `Audio` (`loadedmetadata`); revoke on unmount.
  2. Music: on `playSeq` (while running, uri set) → `device.play([uri], 0)`, HALT on failure. On `level`: `off` → `pause()`; down → `setVolume(target)` at once; up → 10 steps over 500 ms.
  3. Mic: on `state.mic` → set `src`, `play()`; `ended` → CLIP_ENDED, `error`/rejected play → CLIP_FAILED; report a clock every 250 ms; a clip whose entry errored → CLIP_FAILED; null → pause.
  4. Outro timer: when the element on air is a song with an outro talk and the mic is off, arm `setTimeout(OUTRO_DUE, duration − clipLen − TAIL − position)` from the device's last report; re-arm on every report.
  5. Stopped → pause both; unmount → pause the element.
  Plus `unlock()` (silent WAV inside the tap, as the station does).
- [ ] **Step 2: Typecheck** — `pnpm --filter web typecheck`.
- [ ] **Step 3: Commit** — `The program's effects: the device and the mic follow the lanes`.
